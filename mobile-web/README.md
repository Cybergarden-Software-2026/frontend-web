# underCtrl Mobile Web

Отдельное мобильное веб-приложение / PWA для координаторов со своей сборкой и service worker. При публикации Docker размещает его по /mobile/ рядом с основным кабинетом.

React + TypeScript + Vite, Firebase Cloud Messaging, IndexedDB/Web Crypto, шрифты МТС. Установочный APK, Apple Developer и APNs для этой версии не нужны.

## Запуск

Требуются Node.js 24+ и pnpm 11+. Откройте эту папку в VS Code:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

На текущем компьютере также доступен `./scripts/run.sh dev`.

- Разработка: http://127.0.0.1:5174
- `pnpm build` / `./scripts/run.sh build`: TypeScript, приложение и отдельный service worker в `dist`.
- `pnpm preview` / `./scripts/run.sh preview`: собранная PWA на http://127.0.0.1:4174.
- `pnpm test` / `./scripts/run.sh test`: правила хедера, QR-контракт, пагинация, шифрование сессии и постоянство deviceId.

Разработка по умолчанию проксирует `/api` на `https://cybergarden.sosmooth.ru`. `.env.local` может изменить `API_PROXY_TARGET` на тестовый backend. Cookies веб-кабинета не используются: отдельный клиент использует только мобильный Bearer. Секретов и тестовых аккаунтов в коде нет.

## Что уже подключено

1. **QR-вход**: в кабинете найдите QR-код под основным меню, откройте приложение на телефоне и отсканируйте его. Можно вставить полный текст кода вручную. Код не добавляется в URL и не сохраняется.
2. **Сессия**: UUID установки создаётся один раз; при запуске сохранённый Bearer проверяется через `GET /mobile/session`. Ответ 401 очищает сессию и персональный кэш. При недоступной сети доступны ранее сохранённые данные своего аккаунта.
3. **Важное**: GET /mobile/incidents — текущий полный снимок. Главная показывает только три категории хедера: нерешённый P1, больше 8 минут на координаторах и меньше 20% срока до дедлайна. Таймеры идут каждую секунду по серверным часам, включая просрочку. Завершённые карточки уходят из списка; открытая завершённая/закрытая карточка показывает 00:00:00. Исторические события находятся отдельно в журнале.
4. **Журнал**: серверная пагинация `cursor`, дедупликация ID, непрочитанные, подтверждённая сервером отметка чтения. Обновление каждые 15 секунд, при возврате в приложение и после foreground push.
5. **Firebase Web Push**: отдельный веб-клиент `underCtrl Mobile Web` в проекте `underctrl-d087a`. Публичный VAPID-ключ подключён. Токен Firebase отправляется с `fcmTargetType: "token"`. Повторная регистрация после запуска/раз в час учитывает обновление адреса. Права запрашиваются только кнопкой пользователя.
6. **Выход**: `DELETE /mobile/session` отзывает мобильную сессию и серверную привязку push. После успешного ответа удаляются локальная сессия и личный кэш; `deviceId` сохраняется. При ошибке сервера приложение не выдаёт неудачный отзыв за успешный выход.
7. **PWA**: manifest, иконки 192/512 и maskable, offline shell в service worker, безопасные отступы iPhone. Service worker кэширует только статические файлы; ответы API и авторизация в его кэш не попадают.

## Статус backend

GET /mobile/incidents опубликован в рабочей ветке feature/mobile-current-incidents. Клиент уже подключён к контракту {revision,serverTime,items}; production доступен после слияния и выкладки backend. До выкладки сохраняется предыдущий кэш и показывается сообщение о недоступном маршруте.

Снимок полный. При успешном пустом items список очищается. Повторная revision применяется: время и headerKind могут изменяться без новой ревизии. Серверный headerKind используется при получении ответа; между опросами те же правила пересчитываются каждую секунду. Смещение относительно serverTime применяется к таймерам и порогам. Опрос — 15 секунд, при foreground push, возврате из фона, восстановлении сети и вручную.

Nullable-поля заголовка, команды и дат имеют честные пустые состояния. Обычные /snapshot, /incidents и SSE с cookie-сессией веба не вызываются.

Фоновые push backend отправляет только для critical.raised. Ожидание команды и срок показываются на главной; для их push в фоне нужно расширение отправки на backend.

## Хранение токена в вебе

Bearer сохраняется в IndexedDB, зашифрован AES-GCM; ключ создаётся Web Crypto с `extractable: false`, каждый раз используется новый IV. Открытый токен не хранится в localStorage, URL или логах. `deviceId` не меняется при выходе.

Это origin-scoped браузерное хранилище, **не Keychain/Android Keystore**. Код, исполняемый на том же origin, может использовать ключ, поэтому нужны HTTPS, CSP и отсутствие посторонних скриптов. Данные уведомлений находятся в отдельном кэше с владельцем-логином и очищаются при выходе/401. В приватном режиме или при очистке данных сайта устройство может получить новый UUID и потребуется новый QR.

## Установка на телефон

На iPhone с iOS 16.4+: откройте **HTTPS-адрес** в Safari → «Поделиться» → «На экран Домой» → откройте приложение с иконки → подключите уведомления в настройках приложения. APNs-ключ и платная Apple Team для Web Push не требуются.

На Android откройте HTTPS-сайт в поддерживаемом браузере и выберите «Установить приложение»/«Добавить на главный экран». Для проверки на физическом телефоне localhost компьютера не подходит: нужен общий HTTPS-адрес. В development-режиме Firebase push отключён; используйте production build/preview для проверки worker.

## Развёртывание

Это самостоятельный проект, его нужно разместить отдельным origin или в отдельном каталоге существующего HTTPS-сайта. Удобно опубликовать `dist` по `/mobile/`, сохранив тот же `/api/v1`:

```sh
APP_BASE_PATH=/mobile/ pnpm build
```

Не кладите исходники или service-account JSON в web root. Для отдельного домена настройте reverse proxy `/api` на тот же Rust API (или согласуйте CORS и Authorization в backend). Пример Nginx и контракт находятся в `docs/`.

Проверка реальной доставки требует действительного QR, вошедшего координатора, разрешённых уведомлений и тестового события backend. Сборка и модульные проверки не подтверждают доставку на физический iPhone.

Официальные требования: [Firebase Web Push](https://firebase.google.com/docs/cloud-messaging/web/get-started), [Web Push на iOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
